# یادداشت روش و اجرای واقعی

پوشش جاری فقط از reports/progress.json و data/coverage.json نسخهٔ مصرفی خوانده شود. رویدادهای تاریخی زیر، شمارش snapshot نهایی نیستند.

- ساختار ۱۱۴ سوره و ۶٬۲۳۶ آیه از XML تنزیل استخراج و با ناشر AlQuran Cloud بررسی شد؛ snapshot منابع و هش آن‌ها در metadata است.
- پایلوت نهایی شامل ۳۰ آیه از هر ۱۳ مجموعه بود: ۳۹۰ مورد موفق. تلاش‌های مقدماتی و اصلاحات روش در events حفظ شده‌اند؛ تعداد event با تعداد فایل یکتا متفاوت است.
- استخراج اولیه یک batch محدود داشت؛ پس از درخواست ادامه، اجرای کامل بدون سقف زمانی با همان اندازه‌گیر و یک زمان‌بند چندپردازه ادامه یافت. هم‌زمانی DSP برابر ۸ و دانلود هر میزبان حداکثر ۸ است. پارامترها و کد دقیق زمان‌بند در execution-runs ثبت می‌شوند.
- پس از قطع و بازنشانی محیط، snapshot محفوظِ ۶۵٬۱۴۵ مورد شامل ۶۵٬۱۳۵ معتبر و ۱۰ نامعتبر بازیابی شد. نسخهٔ کامل FFmpeg و fingerprint اندازه‌گیری دقیقاً یکسان بودند؛ ادامه فقط موارد باقی‌مانده و خطاهای موقت را در صف گذاشت. اجرای زندهٔ پیش از قطع از ۷۰ هزار مورد گذشته بود، ولی آن پیشرفتِ محفوظ‌نشده به عنوان نتیجهٔ نهایی ادعا نشد.
- ۱۷ آزمون مصنوعی و عملیاتی در محیط بازیابی‌شده نیز گذشت. مرجع رسمی EBU برابر ‎−۲۲٫۹۷۲ LUFS در برابر انتظار ‎−۲۳ بود. این یک آزمون مرجع است، نه گواهی کل مجموعهٔ آزمون EBU یا داوری شنیداری.
- موفقیت return code ابزار برای سلامت Decode کافی نیست؛ خطاهای واقعی فریم با quality_audit قرنطینه می‌شوند. اندازه‌گیری‌های تشخیصی و تاریخچه حذف نمی‌شوند ولی در baseline و Gain وارد نمی‌شوند. هشدارهای comment/lyrics در ID3 از خرابی فریم جدا هستند.
- فایل‌های نامعتبر پس از استخراج یک بار به شکل هدفمند بازدریافت می‌شوند؛ SHA یکسان باعث استفاده از تشخیص قبلی می‌شود و محتوای تغییرکرده دوباره اندازه‌گیری می‌شود. فایل‌های موفق بدون تغییر دوباره دانلود نمی‌شوند.
- پسوند URL مبنای Codec نیست. برای نمونه AlMuiqly/002001.mp3 سربرگ RIFF/WAVE دارد؛ شواهد HTTP Range و Codec در metadata/format-audit.json است. محتوا بدون تبدیل فرمت تحلیل می‌شود.
- هیچ صوت اصلی نرمال‌سازی، trim، بازکدگذاری یا در بستهٔ خروجی توزیع نشده است. فقط فایل‌های موقت دانلود و Decode پس از ثبت نتیجه پاک می‌شوند.
- آستانه‌های ناهنجاری و تغییر پایدار برای مجوّد محافظه‌کارانه‌تر و برای ترجمه حساس‌تر هستند. این‌ها فرضیه‌اند، نه شواهد قطعی تاریخ ضبط. approvals.json خالی است و اصلاح استنباطی خودکار اعمال نشده است.
- سناریوهای ‎−۲۳، ‎−۲۰، ‎−۱۸ و ‎−۱۶ در recommendations جدا هستند. تغییر هدف Gain به دریافت یا Decode مجدد نیاز ندارد. شاخص‌های خام مستقل از هدف باقی می‌مانند.

کد در پکیج @ghoran/audio-analysis از مخزن sabereen/ghoran و برنچ feat/audio-analysis-package است. تغییرات اختصاصی قبلی Qmad به نقطهٔ شروع همان برنچ برگردانده شدند؛ PR مربوط به این کار در Qmad وجود نداشت. PR مخزن مقصد شمارهٔ ۱۳ است.

SQLite عملیاتی، backup قابل حمل، دقیق‌ترین نسخه‌های تاریخی measure.py و pipeline.py، تنظیمات، اندازه‌گیری‌ها، تحلیل‌ها و گزارش داخل ZIP هستند. در صورت وقفه، ادامه با همان نسخهٔ FFmpeg و کد از checkpoint انجام می‌شود؛ تغییر سیاست‌های آماری/Gain نیاز به بازدانلود ندارد. دستور فنی ادامه برای استفادهٔ مجدد در README است؛ اجرای این مأموریت بر عهدهٔ عامل باقی مانده است.
